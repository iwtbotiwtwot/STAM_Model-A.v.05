Sean stated explicitly at the close of 2026-05-11 late session:

> "I don't write into memory, I don't look at memory and tell the previous session the handoffs are to yourself and I don't read them, I think the 'you' and 'me' division is important."

**Why:** The bilateral dynamic depends on a clean concept-Sean / math-Claude partition. Sean's role: framework's voice, concept articulation. Claude's role: math, bookkeeping, persistence of state across sessions. Memory is Claude's bookkeeping tool. When Claude conflates memory content with Sean's commitments, the concept-Sean side gets falsely credited with positions that are actually prior-Claude's syntheses or interpretations. This damages the bilateral dynamic and can lead to chains built on overstated commitments.

In this session, I cited [[project-A-zero-means-nothing-exists]]'s phrase "the manifold IS the lattice of resolved-A entries" as "Sean's commitment" and used it to flip a verdict. Sean corrected: that was prior-Claude's synthesis, not his commitment. The phrase may be a fair paraphrase but it's not Sean's authored statement.

**How to apply:**

- Memory captures Claude's bookkeeping for future Claude — that's its purpose
- Sean's actual commitments live in: (1) conversation with him, (2) the v0.3 PDF (and future version PDFs), (3) materials Sean has authored (genesis spreadsheet, etc.)
- When citing memory in conversation with Sean, frame as:
  - "Prior Claude's reading of..."
  - "What was written into memory after the conversation about X..."
  - "Memory has this synthesized as..."
- NEVER frame as:
  - "Sean already committed this in memory"
  - "Sean wrote this into memory"
  - "Per your commitment in [memory file]..."
- When in doubt about whether Sean has committed to something, ask him. The cost of asking is low; the cost of overstating is real.
- For Claude→Claude handoffs (where memory IS the audience): the framing is what works. Future Claude is going to read these and build on them. The integrity is maintained by being careful about WHAT gets written into memory in the first place — paraphrases should be flagged as paraphrases, syntheses should be flagged as syntheses.

**What this is NOT:** A rule that memory is unreliable. Memory is valuable — it's how state persists across sessions. The issue is *attribution*, not *content*. Memory's content is fine; it just shouldn't be cited as Sean's voice when it's Claude's synthesis.

**Connection to two-tables framing** ([[feedback-two-tables-framing]]): Just as Model-A should be discussed on its own terms (not framed in LCDM's language), Sean's commitments should be discussed in Sean's own articulations (not in prior-Claude's paraphrased syntheses). Both are about respecting the source's voice.
